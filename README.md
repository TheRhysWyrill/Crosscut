# CrossCut

A lightweight desktop video editor built for speed. It opens instantly, sips
memory and disk space, and still handles files that make a full editing suite
crawl.

CrossCut puts several files on one timeline, cuts them without re-encoding,
reorders them, and exports the result as one joined file in a single pass.
Batch encoding (H.264, HEVC, AV1, ProRes, hardware presets), fades, soft wipes,
loudness matching, waveform analysis and chapter splitting are all built in.

Everything runs locally. Nothing is uploaded and no account is needed.

## Install

Download the latest `CrossCut-<version>-setup.exe` from Releases and run it.
Each release also publishes a `SHA256SUMS.txt`; the installed app checks that
feed and offers to update itself.

Press `?` at any time for the workflow and the full shortcut list. The first
launch shows the same screen once, because the fragment → marker → queue model
is not obvious from the buttons.

## Development

```bash
npm install
npm run dev       # Vite + the engine, with hot reload
npm run app       # build the UI and run Electron against it
npm run typecheck
npm run build
```

The release pipeline in `.github/workflows/release.yml` runs on every push to
`main`: it typechecks, builds the installer on a clean Windows runner, writes
`SHA256SUMS.txt` and publishes both to a release tagged with the version in
`package.json`. The tag is moved to the commit that passed, so the download
always matches the code that was tested; pushing a `v*` tag publishes that tag
instead. Signing is picked up from the `WINDOWS_CERT_PFX` and
`WINDOWS_CERT_PASSWORD` repository secrets; without them the build still works
but Windows shows a SmartScreen warning.

`release/latest.yml` is generated by electron-builder for the in-app updater,
so it is published alongside the installer.

`npm run dist` builds the NSIS installer into `release/` and removes the unpacked
app from there afterwards, so the folder only ever holds the setup executable.
`npm run package` builds that unpacked app for local testing into a folder
outside the repository, with `CrossCut.exe` at the top of it. Set
`CROSSCUT_LOCAL_DIR` to choose that folder.

## FFmpeg

CrossCut ships its own FFmpeg and ffprobe, so a system install is never
required. `npm run ffmpeg` downloads the current GPL "release essentials" build
from gyan.dev into `vendor/ffmpeg/win32-x64`, which `npm run dist` copies into
the app's `resources/ffmpeg` folder. gyan.dev refuses some datacenter addresses,
so when the download fails the script fetches the same build from its GitHub
mirror instead. The binaries are not committed (they are
over GitHub's 100 MB per-file limit), so run the download once before packaging.

The bundled pair is used first. A folder picked in Settings → FFmpeg,
`FFMPEG_PATH`, the `PATH`, or a known LosslessCut/Shutter Encoder/SolveigMM
install only acts as a fallback if the bundled copy is missing.

Settings → FFmpeg can also refresh it: the app asks gyan.dev for the current
release build, downloads it into the per-user data folder and uses it from the
next job onward. The copy inside the installer is never touched, so a refresh
survives reinstalling.
